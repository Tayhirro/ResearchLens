# 示例：为什么由主 agent 决定后续调研？

> 本文是基于公开规则整理的讲解示例，展示 ResearchLens 的分析形式。它未执行本 skill 的多 agent 流程，也未测量研究质量或效率。

## 问题与对象

研究对象是本仓库的“后续候选问题调度”设计。问题是：如何允许研究继续深入，同时控制范围扩张？

规则要求子 agent 完成当前任务后，返回证据缺口、反例和后续候选问题。主 agent 合并候选、判断优先级，并决定提升、暂缓、丢弃或解决。[SKILL.md §3.1](../SKILL.md#31-主-agent-调度的迭代深化)

## 前提、替代方案与机制

这个设计依赖两个前提：子问题可以独立描述，主 agent 能判断新问题是否影响原始任务。前提不成立时，拆分可能割裂材料，候选问题的优先级也可能被误判。

另一种可选组织方式是允许子 agent 自行派发后续任务；也可以由一个 agent 全程研究。前者扩大局部探索的自主性，后者减少协调过程。本仓库选择集中调度，把候选发现交给子 agent，把范围和投入判断留给主 agent。

其因果路径是：子 agent 发现缺口 → 返回带来源与影响说明的候选 → 主 agent 合并重复候选 → 只提升影响最终判断的任务。文档直接支持这条组织流程。“它有助于控制范围扩张”是对该设计的合理推断；是否改善实际研究质量，还需要对照任务验证。[调度与综合规则](../SKILL.md#6-主-agent-综合子-agent-结果)

## 证据支持到哪里？

| 判断 | 支持类型 | 依据或缺口 |
|---|---|---|
| 子 agent 不得自行创建子子 agent | 规则直接支持 | §3.1 与子 agent 模板 |
| 主 agent 负责候选合并与提升 | 规则直接支持 | §3.1 与 §6 |
| 这一组织方式有助于限制局部范围扩张 | 综合推断 | 有明确控制路径，尚无本示例的效果测量 |
| 独立上下文能够消除共同偏差 | 未确定 | 文档没有提供能证明这一保证的对照结果 |
| 这一方法优于所有其他组织方式 | 未确定 | 缺少统一任务、预算和评测标准下的比较 |

## 边界与迁移

这个组织方式可类比到长文审查：不同审查者按问题寻找证据，由主审统一决定哪些疑点值得继续查证。也可借鉴到技术选型：各任务调查不同约束与方案，负责人按影响程度决定后续投入。

这些是组织方式的类比，支持类型为综合推断。迁移需要保留三个条件：子任务边界清楚；候选能说明对判断的影响；负责人掌握整体任务与预算。若每个子问题高度依赖其他材料，或负责人无法正确筛选候选，集中调度也可能成为瓶颈。

## 可复用的笔记

这项设计把“发现新的研究问题”和“决定是否继续投入”分开。子 agent 提供带来源的候选，主 agent 依据原始问题统一裁决。可借鉴的原则是：为局部探索保留发现空间，同时让后续投入始终受整体目标约束。文档支持其组织机制，实际收益仍需具体任务检验。
